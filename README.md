# Boss 岗位助手

本地优先、人工确认的 Boss 直聘求职筛选 Chrome 扩展。它先匹配简历，再过滤城市，结合招聘页信息与全网公开资料判断公司可信度，最后生成可编辑的沟通文案。所有消息必须逐条批准并再次确认后才会发送。

当前版本：`0.2.6`，基于 WXT、React 和 TypeScript。

## 工作流

```mermaid
flowchart LR
  A[PDF/DOCX 简历] --> B[简历匹配]
  B --> C[城市过滤]
  C --> D[公司页面信号]
  D --> E[AI 岗位复核]
  E --> F[全网公司核验]
  F --> G[人工逐条批准]
  G --> H[发送前再次确认]
  H --> I[检测发送气泡]
```

## 0.2.0 能力

### 简历与岗位采集

- 本地解析 PDF、DOCX、TXT 和 Markdown 简历。
- 扫描 Boss 推荐岗位时自动滚动加载，滚动轮数上限可配置。
- 在列表末端连续滚动仍没有新岗位时自动停止，不依赖“下一页”按钮。
- 按岗位 URL 中的 `job_detail` ID 去重，避免同一岗位跨页重复。
- 可逐岗位点击卡片读取右侧完整 JD，再用于技能、经验和 AI 匹配。
- 单次扫描默认最多抓取 30 个岗位 JD，数量可调整。
- 目标城市使用省级分组的地级市多选，不接受自由输入的区县文本。
- 配置目标岗位、排除词、匹配阈值、每日上限和发送间隔。
- 简历技能与经历占匹配分的 65%，岗位标题只占 20%。
- 综合排序使用简历匹配 75%、公司可信度 15%、城市便利度 10%。
- Boss 列表只提供公司名和标签时，不会因缺少规模、融资或完整 JD 被误判为公司不可靠。
- 筛选页会直接展示最近岗位的简历、城市、公司或 AI 排除原因。
- 可将历史自动排除岗位按当前规则重新评估，不会改动已批准、跳过或已发送记录。

### AI 岗位复核

- 支持任意 OpenAI 兼容的 `/chat/completions` 接口。
- 支持 DeepSeek、OpenAI、Kimi、通义千问等兼容服务。
- AI 只依据简历原文和岗位原文评分，不允许补造经历、学历或数字。
- AI 不可用或响应格式错误时保留本地规则结果。
- 设置页可测试 AI 连接。

### 公司全网核验

招聘网站展示的公司规模、融资、行业和页面描述会先作为基础信号。启用公司核验后：

1. 使用 Tavily Search 检索公司工商信息、经营异常、失信、诉讼、行政处罚和劳动争议。
2. AI 只依据招聘页信息和检索结果输出保守的可信分、风险标签和结论。
3. 每条 AI 证据必须映射到实际检索结果，不允许生成不存在的来源链接。
4. 达到可信阈值且未发现高风险信号的公司才能进入人工审核。
5. 招聘页中的外部工商和公开信息链接始终保留，供人工复核。

未配置 Tavily Key 时，扩展不会声称完成“全网核验”，只会显示本地页面信号。

### 人工确认与可靠发送

- 所有岗位都需要逐条批准，可编辑或切换三种沟通文案。
- 执行队列前需要第二次确认。
- 队列状态依次经过 `queued → sending → sent`。
- `sent` 只在页面出现新的完整文字气泡后成立。
- 页面通信中断时标记为“需人工确认”，不会自动重试，避免重复发送。
- 失败、阻断或中断岗位必须在发送页显式恢复。
- 遇到验证码、安全验证或未知页面状态立即停止。

### 通知与备份

- 每 5 分钟检测 BOSS 未读消息，出现新回复时发送浏览器通知。
- 可导出完整岗位、审核和发送记录。
- 备份默认排除 AI Key 和 Tavily Key；恢复时沿用当前本机 Key。
- 旧版 0.1 本地数据会自动迁移。

## 快速开始

环境要求：Node.js 22、npm 10 或更高版本。

```bash
npm install
npm run build
```

在 Chrome 打开 `chrome://extensions`：

1. 启用“开发者模式”。
2. 点击“加载已解压的扩展程序”。
3. 选择项目中的 `.output/chrome-mv3`。
4. 固定“Boss 岗位助手”并刷新已打开的 Boss 页面。

开发模式：

```bash
npm run dev
```

## AI 与公司检索配置

在扩展“方案 → AI 岗位复核”中填写：

```text
接口地址：https://api.deepseek.com/v1
模型：deepseek-chat
AI API Key：你的模型服务 Key
```

公司全网核验还需要：

```text
Tavily Search Key
公司可信阈值，默认 70
```

Tavily 返回的搜索摘要只是线索。工商异常、失信、欠薪、劳动争议和行政处罚会降低可信分；扩展不会把搜索结果自动升级为法律事实。

## 使用流程

1. 导入 PDF/DOCX 简历，确认文字提取完整。
2. 填写目标岗位，按省份搜索并多选地级市，再设置排除词和滚动加载轮数。
3. 可选启用 AI 岗位复核和公司全网核验。
4. 打开 Boss 岗位搜索结果页，点击“扫描岗位”。
5. 保持“抓取完整岗位 JD”开启，等待列表滚动和详情读取完成。
6. 在确认页检查 AI 依据、公司可信等级、风险项和来源链接。
7. 修改沟通文案并逐条批准。
8. 在发送页复核队列，完成第二次确认。
9. 保持侧边栏打开；检测到完整发送气泡后才记为成功。

建议首次使用只扫描 1 页、批准 1～2 个岗位，并在真实页面核对发送结果。

## 数据与安全

- 简历、岗位、审批和发送记录存储在 `browser.storage.local`。
- API Key 只保存在本地浏览器扩展存储，不写入备份。
- 启用 AI 后，简历摘要和岗位内容会发送到你配置的模型服务。
- 启用公司核验后，公司名称和公开检索结果会发送到你配置的 AI 服务。
- 扩展不请求 Boss 密码，不读取 Cookie，不使用代理池、账号池或验证码绕过。
- 发送通知和队列均受每日上限、发送间隔和验证页面停机约束。

更多信息见 [架构文档](docs/architecture.md) 和 [隐私说明](docs/privacy.md)。

## 当前限制

- 无限滚动加载依赖 Boss 当前的岗位列表结构，页面改版后需要更新适配器。
- 完整 JD 读取需要逐个点击岗位卡片，岗位较多时扫描会明显变慢。
- 扫描版 PDF 暂不内置 OCR，需要先转成可提取文字的 PDF 或直接粘贴。
- 旧版 `.doc` 不支持，请先转换为 `.docx`。
- 全网公司核验需要 Tavily 和 AI Key；未配置时只能使用招聘页信号。
- 公司可信结果是辅助筛选，不构成法律、财务或商业尽职调查。
- 单次扫描最多对本地得分最高的 12 个岗位调用 AI，控制费用和等待时间。
