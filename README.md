# Boss 岗位助手

一个本地优先、人工确认的 Boss 直聘求职筛选扩展。它先根据简历匹配岗位，再过滤目标城市，然后评估公司页面信号，最后生成可编辑的口语化沟通文案。

项目当前为 `0.1.0` 早期版本，适合个人使用和二次开发。扩展不会绕过验证码、安全验证或平台限制。

## 工作流

```mermaid
flowchart LR
  A[简历匹配] --> B[城市过滤]
  B --> C[公司信号检测]
  C --> D[沟通文案]
  D --> E[人工批准]
  E --> F[二次确认]
  F --> G[受控发送]
```

### 1. 简历匹配

- 从简历提取目标标题、技能、学历、明确写出的工作年限和量化成果。
- 对岗位标题、技能覆盖、经验和学历进行加权评分。
- 命中排除词的岗位直接停止。
- 低于简历匹配阈值的岗位不进入城市阶段。

### 2. 城市过滤

- 支持多个城市。
- 可接受明确标注为远程的岗位。
- 工作地点缺失时不会自动猜测，会标记为未通过。

### 3. 公司信号检测

- 检查公司名称、规模、融资、岗位描述完整度和标签。
- 标记押金、培训费、刷单、私人转账等高风险表述。
- 输出 A / B / C / D 信号等级和人工核验链接。
- 该结果是筛选信号，不是对公司法律或财务状态的认证。

### 4. 沟通与执行

- 根据匹配技能和简历原文证据生成三种文案。
- 每个岗位必须逐条批准，并可自由编辑文案。
- 执行前还需要一次队列确认。
- 默认 30 秒间隔、每日 12 条，可自行调整。
- 遇到验证页面、登录失效、未知弹窗或控件变化时停止。

## 快速开始

环境要求：Node.js 22，npm 10 或更高版本。

```bash
npm install
npm run dev
```

开发构建完成后，在 Chrome 打开 `chrome://extensions`，启用“开发者模式”，加载 WXT 输出目录中的扩展。打开 Boss 直聘岗位搜索结果页，然后点击扩展工具栏图标。

生产构建：

```bash
npm run build
```

加载目录：`.output/chrome-mv3`。打包文件：

```bash
npm run zip
```

## 使用流程

1. 在“方案”中粘贴简历，填写目标岗位、城市和排除词。
2. 打开 Boss 岗位搜索结果页，进入“筛选”扫描当前页面。
3. 在“确认”中查看匹配依据、公司信号和沟通文案。
4. 编辑文案后批准需要的岗位。
5. 在“发送”中复核队列并完成第二次确认。

## 数据与安全

- 简历、岗位和发送记录只保存在 `browser.storage.local`。
- 不请求账号密码，不读取 Cookie，不包含遥测。
- 0.1.0 不调用第三方模型或企业数据 API。
- 已批准但未二次确认的队列不会执行。
- 关闭侧边栏会终止正在等待的发送队列。

更多说明见 [架构文档](docs/architecture.md) 和 [隐私说明](docs/privacy.md)。

## 当前限制

- 只扫描当前页面中已经渲染的岗位卡片，不自动翻页。
- 尚未解析 PDF / DOCX，可直接粘贴文本或导入 TXT / Markdown。
- Boss 页面结构可能变化，需要更新 `src/entrypoints/content/adapter.ts` 和测试夹具。
- 公司检测依赖页面信息和人工复核，不替代工商、司法或财务调查。
- 自动发送受浏览器页面状态影响；找不到沟通入口时会要求人工处理并停止队列。
